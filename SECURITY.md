# Security and maintenance

This is an archived, unsupported source release. There are no supported versions, promised security updates, monitored vulnerability-report inbox, or response-time commitments. Maintain security patches in your own fork. Do not publish credentials or private user data in a public issue or fork.

Use your own provider accounts, budgets, authenticated live deployment, restricted database role, and separate public/private storage. Keep secrets server-side, preserve SSRF and file-containment controls, and review dependency advisories before deploying. The unauthenticated demo is intended for loopback use only.

Live generation can incur third-party charges. Cancellation cannot retract all externally submitted work. Provider and infrastructure billing must also be controlled in their respective dashboards.

If you discover a vulnerability, disable the affected capability in your installation, patch your fork, and coordinate privately with the operators of affected installations or the upstream dependency maintainers when applicable. No report needs to include anyone's real keys, documents, media, or database records.
